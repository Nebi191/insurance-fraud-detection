# Backend runtime dependencies — versions frozen in Phase 0.
#
# WHY EVERYTHING IS PINNED WITH `==`:
# `models/pipeline.pkl` is a joblib/pickle file, and the then-current classes of
# scikit-learn, numpy, scipy and lightgbm are serialised inside it. If a
# different minor version is resolved in the Docker image, the pickle either
# fails to load with `AttributeError` / `ModuleNotFoundError`, or — worse —
# behaves differently in silence and the deploy breaks. The versions are taken
# verbatim from `pip freeze` output; none of them were guessed.
#
# PYTHON VERSION: 3.14.6 (pipeline.pkl was produced with this interpreter).
# The Dockerfile must use the `python:3.14-slim` base. An older Python (3.11,
# say) may be able to open the pickle, but that is not guaranteed.
# The current training environment is also recorded in models/metadata.json ->
# library_versions.
#
# THIS FILE IS THE ONLY ONE THE DOCKERFILE INSTALLS (Phase 7).
# Test and lint dependencies live in `requirements-dev.txt` — no test package
# belongs in a production image (image size + needless attack surface). For
# local development, install `requirements-dev.txt` instead; it pulls this file
# in via `-r requirements.txt`, so one command still gets you everything.
